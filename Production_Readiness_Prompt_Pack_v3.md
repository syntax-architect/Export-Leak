# Part 1. Your test-data problem, solved without knowing any exporter

You are right that you cannot just "get" real shipping bills. Here is the honest answer: **you can reach about 80% confidence without a single real document, and the last 20% needs 5 to 10 real ones.** Use three layers, in this order.

| Layer                              | What it proves                                                                    | Where the files come from                                           | Who does the work                                                     |
| ---------------------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------- | --------------------------------------------------------------------- |
| **1. Synthetic Document Lab**      | Your logic is correct: parsing, matching, rate maths, deadlines                   | Generated by code, with the correct answer saved next to every file | Prompts P4 and P5 below (I can also generate the files for you later) |
| **2. Official-source checks**      | Your layouts, rules and rate numbers match what the government actually publishes | Public official documents (list below)                              | You, with the checklist in Prompt P6                                  |
| **3. Real documents with consent** | Your parser survives real-world mess (scans, odd layouts)                         | 5 to 10 files from consultants who agree to a free audit            | You, using the outreach text below and Prompt P7                      |

**Important limit:** layer 1 tests your _logic_, not the _variety of real layouts_. Never claim "works on real documents" until layer 3 has passed. Until then, every result in the app should say "estimate, please verify".

## How you will know the output is good

Do not judge by "it looks right". Use a scoreboard. The app passes only when **every line** passes:

| Check                  | How                                                                        | Pass mark                                                                           |
| ---------------------- | -------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Extraction accuracy    | Compare parser output with the saved correct answer for every field        | 98% of required fields correct or flagged for review; under 1% wrong without a flag |
| Money-critical fields  | Invoice value, FOB, currency, HS code, shipping bill number and date, port | 100% correct or flagged. Never a silent error                                       |
| Matching               | Payment-to-shipment matches vs the known pairs                             | Zero wrong auto-confirmed matches; ambiguous cases always go to review              |
| Incentive maths        | Recalculate 30 cases by hand or spreadsheet; compare with the app          | Exact to the rupee after documented rounding                                        |
| Rate data              | Pick 25 HS codes at random; compare with the official notification         | 25 of 25 match                                                                      |
| Deadlines              | Calendar test on month-end, leap-year and the 1 Oct 2026 rule change       | 100%                                                                                |
| Messy input            | Scans, tilted pages, phone photos, partial pages                           | Never crashes; low confidence is shown; user can correct                            |
| Real documents (later) | 5 to 10 real files with consent                                            | Same thresholds as the first row                                                    |

**Rule for the product:** every number the app shows has a "Show working" link, a confidence label, and the words "Estimate. Verify with your CA or AD bank."

## Getting real documents when you know no exporters

1. Offer **free audits** to export consultants and CHAs. Reach them on LinkedIn and in export-promotion-council communities. Send 10 to 15 messages a day.
2. Ask for only 3 to 5 old, fully completed shipments, with company names blacked out if they prefer.
3. Get written consent (a short WhatsApp or email "yes" is enough), then use Prompt P7 to redact and store them privately.
4. Message template (edit as you like):

```
Hi [Name], I am building a small tool that finds unclaimed RoDTEP/drawback and
missed payment deadlines for exporters. I would like to run a free audit on 3 to 5 of
your COMPLETED shipments (names can be hidden). You keep full control: I delete the
files after the test, and you get a one-page report of any money or deadlines that
were missed. Would you be open to a 15-minute call this week?
```

## P11. Security hardening (gaps found in the review)

```
GOAL
Close the specific gaps I found and re-test everything that touches money or private files.

FIXES
1. Rate limiting: lib/rate-limit/memory-rate-limiter keeps counters in server memory. On serverless hosting each instance has its own memory, so limits can be bypassed. Move to a shared store (Upstash Redis, or a Postgres table with atomic counters). Keep the memory limiter only for local development. Apply to login, signup, password reset, upload, free tools, webhooks (by source), invite and share links. Add tests that simulate two instances.
2. Test-only code in production: /api/auth/force-login and the in-process PGlite adapter are protected only by a NODE_ENV check. Make them impossible to reach in production: exclude them from production builds (build-time flag), fail the production build or boot if EXPORTLEAK_FORCE_DEV_LOGIN or the PGlite adapter is enabled, and add a CI test that requests /api/auth/force-login against a production build and expects 404.
3. Environment validation: validate all environment variables with a Zod schema at boot. Production refuses to start if any secret is missing, a placeholder, a test Razorpay key in production, or the cron secret is shorter than 32 characters.
4. Cron and internal routes: require the bearer secret with constant-time compare (already present for generate-alerts; verify every internal route), add replay protection and IP logging, and document the secret rotation steps.
5. Files: scan uploads (type sniffing, size, page and zip-bomb limits), store with random names, serve only via short-lived signed URLs, and never render user-supplied PDFs or HTML inline without sandboxing.
6. Share links: unguessable tokens, expiry, revoke, view counting, and totals-only content (test that no row-level data leaks).

Try to read another organisation's data through every route and server action, activate a paid plan without a valid webhook, forge or replay a Razorpay webhook, bypass plan limits through direct API calls, upload a malicious file, find secrets in the client bundle, cause double billing. For each finding give severity, file and line, reproduction and fix; fix all High and Critical; add a regression test for each. Update /docs/SECURITY_REVIEW_REPORT.md.
